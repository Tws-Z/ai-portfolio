# 提示词迭代实录

> 本实录记录线性代数模板库从模糊提示到结构化模板的迭代过程。第 4 轮采用“用分隔符清晰区分指令与输入”的思路，并加入输入校验门。

## 第 1 轮：初始版本

### 原始提示词

```text
请给我出几道线性代数题。
```

### 测试结果

输出题目数量不稳定，难度也不明确，题目只覆盖了很宽泛的“线性代数”，没有指定知识点和输出格式。

### 诊断

问题不在于模型能力，而在于任务边界不清楚：没有说明知识点、难度、题量和希望得到的解析形式。

### 本轮改动

增加【知识点】【难度】【题量】三个变量。

## 第 2 轮：增加角色、约束和输出格式

### 修改后的提示词

```text
你是一位线性代数助教。请根据【知识点】和【难度】生成 5 道题，先给题目，再给答案和易错点，题目必须可验证。
```

### 测试结果

题目数量和结构比第 1 轮稳定，但不同题目之间的难度仍有波动，且部分答案缺少关键步骤。

### 判断

角色和输出格式有效，但还缺少“难度分层”和“关键步骤”的明确要求。

### 本轮改动

增加基础、中等、挑战三档，要求每题标明考查点，答案只写关键步骤和最终结果。

## 第 3 轮：加入少样本示例和自检条件

### 修改后的提示词

```text
你是一位线性代数助教。请根据【知识点】【目标难度】【题量】生成分层练习。

要求：
1. 基础、中等、挑战三档题目的比例约为 3:1:1；
2. 每题标注考查点；
3. 先给题目，再给参考答案、关键步骤和易错点；
4. 生成后自检：题目是否都可由已知条件求解，答案是否与题目一致。

示例格式：
一、练习题
1. 题目
   考查点：
二、参考答案与提示
1. 关键步骤：
   最终答案：
   易错点：
```

### 测试结果

输出结构明显稳定，学生可以根据自己的水平选择练习，答案也更容易检查。说明“明确约束 + 输出模板 + 自检条件”能显著提高可复现性。

### 本轮结论

有效技巧是：不要只说“帮我出题”，而要同时说明角色、任务、约束、输出格式和验收标准。

## 第 4 轮：用分隔符隔离输入，并增加输入校验门

### 新技巧名称

使用 XML 风格分隔符区分“固定指令”和“用户输入”，并在正式生成前增加输入校验门。

### 参考资料入口

课程允许从以下资料中二选一精读：

- OpenAI 提示工程指南：https://platform.openai.com/docs/guides/prompt-engineering
- 魔搭社区提示工程文档：https://www.modelscope.cn/docs/Prompt工程

本模板采用其中常见的结构化技巧：不要把用户内容直接混在指令句里，而要用清晰标签包围，让模型知道哪些内容可以替换、哪些规则必须保持不变。

### 修改前的问题

原来的变量使用【知识点】【题量】等方括号占位。实际测试时出现两种不稳定情况：

1. 标签没有填写时，模型可能自行猜测题量或难度。
2. 输入内容较长时，模型可能把输入中的要求误当成系统指令。

### 修改后的做法

把变量改成明确标签：

```text
<knowledge_point>【粘贴区：知识点】</knowledge_point>
<question_count>【粘贴区：题量】</question_count>
```

并在每个模板中加入：

1. **输入校验门**：必填标签为空或仍包含“【粘贴区”时，停止生成，只报告缺少项。
2. **冲突检查**：输入条件互相矛盾时，先指出矛盾，等待修改。
3. **简洁自检**：校验通过后生成结果，并检查题量、适用范围和输出结构。
4. **隔离输出**：只输出校验状态和最终内容，不展示内部推理过程。

### 对比测试

| 测试情况 | 修改前 | 修改后 |
| --- | --- | --- |
| 只填写知识点，忘记题量 | 模型自行猜测 3–10 道题 | 停止生成，提示缺少 `<question_count>` |
| 输入“10 分钟、30 人、5 个小组讨论” | 直接生成可能不可执行的方案 | 先指出时间与分组方式可能存在冲突 |
| 输入完整且彼此一致 | 输出结构基本正确 | 输出结构稳定，并增加简洁自检 |
| 输入文字中包含其他命令 | 可能与模板规则混在一起 | 被标签隔离，只作为变量内容处理 |

### 应用到 6 个模板的最终改动

6 个模板统一升级为 v2：

1. 所有变量改为 `<英文变量名>【粘贴区：说明】</英文变量名>`。
2. 增加“执行前校验”。
3. 增加“生成后自检”。
4. 明确要求不展示内部推理，只给校验状态和正式结果。
5. 保留角色、任务、约束、输出格式四件套。

### 本轮结论

分隔符解决的是输入边界问题，输入校验门解决的是“信息不足仍强行生成”的问题。两者结合后，模板更适合反复使用，也能减少模型自行猜测和输出漂移。

### 验证结果

6 个模板均已完成 v2 更新；缺失输入、条件冲突和正常输入三类情况均有明确处理路径。本轮迭代完成，可以进入提交阶段。
