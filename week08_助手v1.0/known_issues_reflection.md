# 为什么 README 的「已知问题」要诚实写

README 的已知问题不是给自己的项目“挑毛病”，而是帮助使用者建立正确预期。如果只写功能和优点，别人可能把本地 0.5b 当成可靠的标准答案来源，直接用它处理 HSK 数字、学生评价或正式教学材料，最终造成事实错误。诚实写出本地模型能力有限、2021 标准与旧版 HSK 口径不同、Chroma 换资料后要重建、云端密钥和 Ollama 可能失败，使用者才能知道哪些任务需要人工核验、哪些情况应改用云端或先做脱敏。已知问题也方便未来的自己复现和排错：它把踩过的坑变成可执行的检查清单，而不是隐藏成本。项目可以暂时不完美，但必须让使用者清楚边界，这是工程责任，也是对教学数据负责。
