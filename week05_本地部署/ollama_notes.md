## 2. 安装与运行步骤

### 启动服务

```powershell
$env:OLLAMA_MODELS = "E:\Project\Logs2\W3\ollama_models"
$env:OLLAMA_HOST = "127.0.0.1:11434"
E:\Project\Logs2\W3\tools\ollama\ollama.exe serve
```

服务启动后会监听 `127.0.0.1:11434`。本机没有独立显卡，Ollama 自动选择 CPU 推理；集成显卡被跳过。

### 拉取和运行模型

```powershell
ollama pull qwen2.5:0.5b
ollama list
ollama run qwen2.5:0.5b "用一句话介绍你自己。"
ollama ps
```

### 查看模型与运行占用

```text

```

本次还把模型目录设置为 E 盘，因此模型文件没有写入 C 盘。

## 3. 为什么选择 0.5b

本机只有 8GB 内存，且没有独立显卡。根据讲义选型原则：

- 8GB 内存：适合 0.5b–1.5b；
- 16GB 内存：才可以考虑 4b 量化模型；
- 32GB 以上：才考虑 8b 模型。

因此：

- 主用模型：`qwen2.5:0.5b`，体积约 397MB，启动快，适合格式固定、结果可人工检查的任务。
- 作业 2 对比模型：`qwen2.5:1.5b`，体积约 986MB，质量略好，但速度更慢、内存占用约 1.1GB。
- 不选择 4b/8b：不是模型不好，而是本机内存和核显条件不够，勉强运行会频繁换页，课堂演示容易卡顿。

## 5. 作业 2：0.5b 与 1.5b 的对比

下载 `qwen2.5:1.5b` 后，用同一组 5 个问题测试：

| 项目 | qwen2.5:0.5b | qwen2.5:1.5b |
| --- | --- | --- |
| 模型体积 | 397MB | 986MB |
| 运行占用 | 约 458MB | 约 1.1GB |
| 冷启动 | 3.86s | 5.97s |
| 平均热调用 | 约 11.31s | 约 18.12s |
| CPU 速度 | 约 24.8–26.1 tok/s | 约 11.7–12.4 tok/s |
| 质量 | 结构简单，错误较多 | 结构更完整，但仍有事实错误 |
| 是否值得升级 | 适合速度和格式固定任务 | 质量有提升，但速度下降明显，不能替代云端 |

1.5b 的典型错误：把 HSK4 词汇量答成约 5500 个，仍不符合考试标准。因此“模型变大一点”不等于“可以不做人工核验”。

完整原始回答和计时保存在：

- `w5_compare_1.5b.json`

结论：

- 0.5b 适合：格式固定、答案容易人工校验、需要快速响应或断网运行的辅助任务。
- 1.5b 适合：本机内存有限但仍愿意等待、需要比 0.5b 稍好一些的文本组织能力时。
- 云端适合：需要准确事实、复杂学科推理、较长教案和高质量评语的任务。
- 任何本地小模型的输出都必须人工复核，不能直接作为学生评价或正式教学材料。

## 6. 量化与 MCP

| 术语 | 它是什么 | 一句话区分 |
| --- | --- | --- |
| 量化 Quantization | 把模型权重从高精度压缩为低精度，减少体积和内存占用 | 量化让模型“装得进小内存” |
| MCP Model Context Protocol | 让模型连接外部工具和数据的通信协议 | MCP 解决“模型怎样使用外部工具”，不是模型压缩 |

因此，“用 MCP 把模型塞进小内存”是错误的说法。本机能把 0.5b 装进 8GB 内存，主要靠模型本身参数小和量化，不是 MCP。

## 7. 官方文档阅读记录：3 条以前不知道的用法

1. `ollama show <模型名>` 可以查看模型的参数、模板、系统提示词和量化信息，比只看 `ollama list` 更详细。
2. 可以通过 Modelfile 和 `ollama create` 创建自定义模型，把常用的中文教学系统提示词、温度等参数固定下来。
3. Ollama 的 API 支持 `keep_alive` 以及 `/api/chat` 等接口，可以控制模型在多长时间内保持加载，也能用 Python/requests 直接连接本机服务；本机实测需要设置 `trust_env=False`，避免 localhost 请求被系统代理接管。

参考资料：Ollama 官方文档 <https://docs.ollama.com/>。

## 8. 隐私边界

### 不应上云

- 学生作文、作业原件、成绩和评语；
- 未公开教案、试卷、校本题库；
- 含姓名、学号、人脸、联系方式等可识别信息的材料；
- 学校内部文件和未发表研究数据。

### 可以上云

- 公开教材、公开课文和通用知识问题；
- 已完成脱敏、无法识别个人身份的材料；
- 自己愿意公开的代码、文档和提示词模板。

判断标准：如果这些数据出现在别人的服务器上，我是否会承担责任？如果会，就应该优先使用本地模型；如果必须上云，要先删除姓名、学号和其他可识别信息。

## 9. 作业 3：无网乡村学校离线部署复盘

如果要在没有网络的乡村学校教室部署，我会提前准备一个“离线部署包”：

1. **离线包**：在出发前下载并校验 Ollama Windows 便携包、模型文件和常用依赖，至少准备一份备用 U 盘；不能依赖现场临时下载。
2. **模型选择**：优先选择 0.5b–1.5b 的量化模型，保证 8GB 内存的旧电脑能启动；不追求 4b/8b，否则容易出现内存不足和课堂卡顿。
3. **内存预算**：Ollama 程序本身、模型常驻和浏览器/投影软件要同时计算。8GB 机器以 0.5b 为主，1.5b 作为可选；准备关闭后台程序的操作清单。
4. **数据目录**：提前把 `OLLAMA_MODELS` 指向空间充足的非系统盘，避免 C 盘被模型占满。
5. **离线验证**：出发前断网实测 `ollama serve`、`ollama list`、`ollama run` 和一次完整问答，记录启动时间和故障处理步骤。
6. **教学内容准备**：把固定格式的出题、改写、词汇解释等低风险任务放在本地；需要高质量推理的任务提前准备云端结果的离线备份，课堂上再人工校对。

## 10. 排错记录

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 官方下载约 1MB/s，耗时过长 | 网络速度限制 | 使用迅雷下载官方 URL，并校验 SHA256 |
| C 盘空间紧张 | 默认程序/模型可能写入系统盘 | 使用官方便携包放 E 盘，设置 `OLLAMA_MODELS` 到 E 盘 |
| 服务未启动 | 便携版不会自动注册开机服务 | 手动运行 `ollama.exe serve` |
| Python 连不上 localhost | 系统代理可能接管 localhost | `requests.Session().trust_env = False` |
| 0.5b 回答事实错误 | 小模型能力有限 | 人工核验；高质量任务改用云端模型 |
| 1.5b 更慢 | 参数量更大，本机只有 CPU 推理 | 保留 0.5b 做主模型，1.5b 只用于质量对比 |
