# W9 工具调用轨迹记录

## 测试环境

- Python 3.13.12
- 模型：DeepSeek `deepseek-chat`（成功轨迹）
- 工具实现：`week09_工具调用/tool_agent.py`
- 工具列表：`get_time`、`calc`、`hsk_level`、`lesson_difficulty`
- 计算器：白名单 AST，不使用裸 `eval`

## 轨迹 1：复合问句，两轮调用

### 原始问句

```text
请依次查询两件事：1. '把'字的 HSK 等级是多少？2. 现在的时间是多少？
```

### 第 1 轮模型输出

```json
{"tool": "hsk_level", "args": ["把"]}
```

### 工具返回

```text
hsk_level['把'] → 把 是 3 级
```

### 第 2 轮模型输出

```text
“把”字的 HSK 等级是 3 级。

接下来查询当前时间：

{"tool": "get_time", "args": []}
```

### 工具返回

```text
get_time[] → 2026-11-16 13:03:47.600723
```

### 最终回答

```text
现在的时间是 2026年11月16日 13:03:47。

两件事查询完毕：
1. “把”字为 HSK 3 级；
2. 当前时间为 2026-11-16 13:03:47。
```

### 点评

模型先查 HSK 等级，再在下一轮决定查时间；两次工具结果都被回喂，最终回答同时包含两个结果。

## 轨迹 2：安全四则运算

### 原始问句

```text
请用计算器计算 35*24 等于多少。
```

### 第 1 轮模型输出

```json
{"tool": "calc", "args": ["35*24"]}
```

### 工具返回

```text
calc['35*24'] → 840
```

### 最终回答

```text
35 × 24 = 840
```

### 点评

模型没有把算术交给语言能力猜测，而是调用了 `calc`。`calc` 使用白名单 AST，只允许数字和 `+ - * / ** %` 等白名单运算。

### 安全反例

```python
calc("__import__('os').getcwd()")
```

实际返回：

```text
拒绝计算：只允许数字与 + - * / ** % 运算
```

没有执行传入的 Python 代码。

## 轨迹 3：第 4 个工具——课文难度评估

### 原始问句

```text
请用课文难度工具评估这段课文相对 HSK4 的难度：愚公移山讲述了愚公带领子孙挖山的故事。
```

### 第 1 轮模型输出

```json
{"tool": "lesson_difficulty", "args": ["愚公移山讲述了愚公带领子孙挖山的故事。", "4"]}
```

### 工具返回

```json
{"target_level": 4, "total_units": 14, "in_level_count": 0, "out_of_level_count": 2, "unknown_char_count": 12, "coverage_rate": 0.0, "out_of_level_words": ["愚公", "愚公移山"], "unlisted_segments": ["讲述了", "带领子孙挖山的故事"], "note": "基于 data/生词表.csv 的样例词典，结果需人工复核"}
```

### 最终回答摘要

模型根据工具结果指出：课文相对 HSK4 偏难；超纲词包括“愚公”“愚公移山”；未收录片段包括“讲述了”“带领子孙挖山的故事”；并提示样例词典需要人工复核。

### 点评

第 4 个工具能接收两个参数：课文文本和目标等级，并返回覆盖率、超纲词和未收录片段。由于 `生词表.csv` 是样例词典，覆盖率不能直接当作正式教材评估结论。

## 失败案例会诊：本地小模型选错工具和参数

使用本地 `qwen2.5:0.5b` 复现：

### 原始问句

```text
把字是几级？现在几点了？
```

### 第 1 轮模型原始输出

```json
{"tool": "calc", "args": [""], "msg": "现在几点了？"}
```

### 实际工具返回

```text
calc[''] → 拒绝计算：invalid syntax (<unknown>, line 0)
```

### 第 2 轮模型原始输出

```json
{"tool": "get_time", "args": [""]}
```

### 实际工具返回

```text
工具执行失败：get_time() takes 0 positional arguments but 1 was given
```

### 最终返回

```json
{"tool": "get_time", "args": [""]}
```

### 失败原因

1. 0.5b 把“HSK 等级查询”误选成了 `calc`，属于选错工具。
2. `calc` 的参数为空，`get_time` 多传了一个空参数，属于参数错误。
3. 达到 `max_calls` 后仍输出工具 JSON，程序把原始 JSON 当成了最终回答，用户拿不到可读答案。

### 约束改法

- 给 `TOOLS` 增加按工具区分的参数数量/类型校验：`get_time` 必须 0 个参数，`calc` 必须 1 个字符串，`hsk_level` 必须 1 个字符串，`lesson_difficulty` 必须 2 个字符串。
- 工具参数错误时，把“参数错误 + 正确格式示例”回喂给模型，要求它重新输出调用；不要直接把原始 JSON 返回给用户。
- 对“复合查询”使用明确编号指令，或使用云端/更大的本地模型；0.5b 不适合承担复杂工具选择。
- 达到最大轮数仍没有自然语言答案时，返回明确的“工具调用未完成，请重试”，并在轨迹中保留原始 JSON。

## 结论

3 条成功轨迹分别验证了 HSK 查询、当前时间、算术计算和课文难度评估。失败案例证明：工具调用循环不仅要能执行正确调用，还必须校验参数、限制轮数，并在失败时把原始错误转化为可执行的提示。
## 失败案例修复后实测

在加入 `TOOL_ARGS` 参数校验和“达到最大轮数不再返回裸 JSON”的收口保护后，本地 0.5b 复测现象：

### 第 1 轮模型输出

```json
{"tool": "get_time", "args": []}
```

### 工具返回

```text
get_time[] → 2026-11-16 13:09:17.726457
```

### 第 2 轮模型输出

```json
{"tool": "get_time", "args": [""]}
```

### 工具返回

```text
工具参数数量错误：get_time 需要 0 个参数，实际收到 1 个
```

### 第 3 轮模型输出

```json
{"tool": "get_time", "args": []}
```

### 工具返回

```text
达到最大工具调用轮数
```

### 最终返回

```text
工具调用未完成：模型在达到调用上限后仍在请求工具。请重试或改用云端模型。
```

### 修复效果

- 参数校验阻止了空参数和多参数直接进入工具函数。
- 达到调用上限后不再把工具 JSON 原样返回给用户，而是返回明确的失败提示。
- 复杂工具选择仍建议使用云端模型或更大的本地模型；0.5b 不适合作为最终工具调度器。
